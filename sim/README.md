# 豊穣の水田 v0.2（水系リデザイン）— ルールエンジンと自己対戦シミュレーター

今の `online/` とは別系統の、作り直し版の検証用コード。UI はなく、ルールの計算とボット同士の自己対戦だけを行う。
**AIは使っていない（Node.js だけで動く）ので、手元のPCで何局回しても無料。**

## 動かし方（Windows / Mac 共通・Node.js 18 以上）

```bash
cd sim
node test.mjs                      # 計算の正しさの確認（数秒）
node exp.mjs configs/timing.json   # 献上を始める年・札の強さ（600局・約6分）
node exp.mjs configs/default.json  # 勝ち筋4種を全席順で比較（48局）
node exp.mjs configs/seat.json     # 席順の有利不利（全員同じボット・600局）
```

画面に表が出て、最後の1行に **「Claude に貼る用」の短いJSON** が出る。それだけ貼れば分析できる。詳しい結果は `results/` に保存される。

数値を変えて試すときは `configs/` にJSONを足し、`params` に `engine.mjs` の `DEFAULT_PARAMS` の項目を書く。

```json
{ "label": "水路を安く", "mode": "random", "games": 600, "params": { "canalCostPerLen": 1 } }
```
- `mode: "random"` … 毎局、席ごとに勝ち筋と献上開始年をランダムに選ぶ（勝ち筋・開始年・札の強さを一度に見る）
- `mode: "lineup"` … `lineup` の顔ぶれを全席順で回す（`gpp` は1席順あたりの局数）
- 局数の目安：勝率の誤差は 150局で±7ポイント、600局で±4ポイントほど

## ルール v0.2（要約）
- 中央の水源から人数ぶんの川。各川に上流・中流・下流の節、各節に区画3つ。各自は自分の川の下流に田2枚で開始
- 1年＝春・夏・秋＋冬。5年
  - 春・夏の頭：**田植え**（全員同時。種代1俵／枚）
  - 各季節：働き手2人を、1枠1人の行動に交互に置く → 水の流れ → 収穫
  - 冬：維持費（働き手1人1俵＋上流の田1枚1俵、払えない分は−1点/俵）→ 献上
- 行動（枠は人数−1、溜池・堰は1）：開墾（上3/中2/下1俵）・水路（長さ×2俵）・手入れ（田3枚まで今年の収量+1）・札（2＋持っている枚数 俵）・溜池（4俵）・堰（6俵）・日雇い（+1俵、枠なし）
- 水の流れ：降水を川ごとに均等 → 上流の節から順に、その節で取る田（その節の田→水路で引いている田）が必要量まで取る → 余りは末端の溜池へ
- 収量＝地力（上4/中5/下6）− 不足した水 ＋ 品種補正 ＋ 手入れ
- 品種（春・夏・秋の必要水量／補正）：早稲 2・1・−／0、中稲 1・3・1／+1、晩稲 −・2・3／+1（台風30%で−3）
- **点は点数トラックにその場で加算。入るのは2つだけ**
  - 建設：部品に印刷された点（田1・水路は長さ1につき1・溜池3・堰3）
  - 献上：3俵あたり 3・3・2・2・1点（年ごとに下がる）
- 札：3枚が表向き。取ると効果は永続。同じ系統（水・時・景色）を3枚そろえると+5点

| 札 | 系統 | 効果 |
|---|---|---|
| 渡来の技術者 | 水 | 水路の費用が長さ1あたり1俵安い |
| 寺社の荘園 | 水 | 上流の田の堤維持費がかからない |
| 溜池造りの名人 | 水 | 溜池が2俵安く、貯水の上限+2 |
| 水口の番人 | 水 | 自分の中稲は夏の必要水量−1 |
| 国司の縁者 | 時 | 献上を前の年のレートで換算できる |
| 早稲の種籾 | 時 | 自分の早稲の収量+1 |
| 采女の家 | 時 | 1・2年目の献上は3俵ごとに+1点 |
| 墾田の民 | 景色 | 開墾の費用−1俵 |
| 篤農家 | 景色 | 手入れで対象にできる田+2枚 |
| 名主 | 景色 | 開墾するたび+1点 |

## 分かったこと

### v0 → v0.1
| 発見 | 対応 |
|---|---|
| 取水口を所有制にすると、上流を開墾しても水が来ない死に田ができる | 取水口を廃止 |
| 植付が1枠2枚だと土地を広げる意味がなく、働き手の約7割が日雇い | 植付枠の拡大・働き手2人・手入れ追加 |
| 献上はいつ出しても1俵＝1点で、最終年まで溜めるのが常に最善 | v0.2 でレートを年ごとに下げた |

### v0.2（300局・ランダム方針）
| 項目 | 結果 | 判定 |
|---|---|---|
| 席順 | 植付を配置の枠にすると、手番が後ろの人が春に植えられず勝率9〜13%に沈んでいた（ルールの欠陥）。全員同時の田植えにしてからは 24/24/23/30% | ほぼ解消 |
| 献上を始める年 | 1年目20%・**2年目38%**・3年目31%・4年目22%・5年目12% | **山型になった**（早すぎても遅すぎても負ける） |
| 勝ち筋ごとの最適な開始年 | ほとんどの勝ち筋で2年目、水路網だけ3年目寄り（1組あたり12局前後なので誤差が大きい） | 「2年目が唯一の正解」になりかけている |
| 勝ち筋 | 札30%・貪欲31%・上流27%・下流24%・**水路網13%** | 上流は v0.1 の1〜8%から大きく改善。水路網はまだ弱い |
| 品種 | 中稲52%・早稲35%・晩稲14% | 死に手なし |
| 札 | 国司の縁者は持っていた人の勝率45〜49%で強すぎ。渡来の技術者12%・溜池造りの名人9〜20%・名主14〜16%は弱い | 調整が必要 |
| 行動 | 日雇い27%・手入れ28%・開墾20%・水路15%・札6% | 日雇いはまだ多め |

### 次に試すこと
1. 水路網の強化：水路の費用を下げる（`canalCostPerLen: 1`）か、水路の印刷点を上げる（`printed.canalLen: 2`）
2. 国司の縁者を弱める／渡来の技術者・名主を強める
3. 献上の最適な年が勝ち筋ごとにもっとずれるか（600局以上で確認）

### 注意（忖度なし）
- ボットは「典型的な1年の収量の増分×残り年数」で判断する単純な先読みで、人間の上級者より弱い。**ボットの下手さを戦略の弱さと取り違える危険**がある（札の価値は特に手書きの見積もりなので怪しい）
- 勝率の誤差は150局で±7ポイント程度

## ファイル
- `engine.mjs` … ルール本体（純関数。将来UIからもそのまま使う想定）
- `fast.mjs` … ボットが評価に使う高速版の1年計算（`test.mjs` で本体と一致を確認）
- `bots.mjs` … 勝ち筋ボット（上流・下流・水路網・札・貪欲）。方針は「勝ち筋＋献上を始める年」
- `run.mjs` … 自己対戦と集計／`exp.mjs` … 実験の実行と表示／`configs/` … 実験の設定
